## 1. Подключение

| Параметр           | Значение по умолчанию  | Настраивается через                   |
|--------------------|------------------------|---------------------------------------|
| Брокер             | `broker.emqx.io`       | `config.json` → `server`             |
| Порт               | `1883`                 | `config.json` → `port`               |
| Авторизация        | не требуется           | `config.json` → `user`, `mqtt_pass`  |
| Device ID          | `A0001`                | прошивка (`device_id[]`)             |
| UTC offset         | `10800` (UTC+3)        | `config.json` → `utc_offset_sec`     |

Все настройки соединения читаются при старте из `/config.json` на LittleFS. При отсутствии файла используются значения по умолчанию.

## 2. Топики

| Топик                  | Направление         | Описание                                     |
|------------------------|---------------------|----------------------------------------------|
| `/Gomel/Tar/sensors/`  | ESP32 → клиент      | Телеметрия сенсоров, каждые 30 с             |
| `/Gomel/Tar/modules/`  | Клиент → ESP32      | Команды управления модулями и расписанием    |
| `/Gomel/Tar/response/` | ESP32 → клиент      | Ответ на каждую принятую команду             |

> Топики переопределяются через `config.json`: поля `topic_sensors`, `topic_modules`, `topic_response`.

---

## 3. Данные сенсоров

ESP32 публикует JSON в топик `topic_sensors` каждые 30 секунд.

### Формат

```json
{
  "device_id": "A0001",
  "data": [
    { "SensorId": 1, "Type": "randomNumber", "Value": 42.0, "Unit": "-" }
  ]
}
```

### Сенсоры

| SensorId | Type              | Unit  | Описание                     | Статус      |
|----------|-------------------|-------|------------------------------|-------------|
| 1        | `randomNumber`    | `-`   | Случайное число (тест)       | ✅ активен  |
| 1        | `airTemperature`  | `C`   | Температура воздуха (BME280) | ⏸ отключён |
| 2        | `airHumidity`     | `%`   | Влажность воздуха (BME280)   | ⏸ отключён |
| 3        | `pressure`        | `Pa`  | Атмосферное давление (BME280)| ⏸ отключён |
| 4        | `plantHeight`     | `cm`  | Высота растения (УЗ)         | ⏸ отключён |
| 5        | `light`           | `%`   | Освещённость                 | ⏸ отключён |
| 6        | `soilTemperature` | `C`   | Температура почвы            | ⏸ отключён |
| 7        | `soilMoisture`    | `%`   | Влажность почвы              | ⏸ отключён |

> Набор активных сенсоров определяется вызовами `info.addSensorInfo(...)` в `setup()`.

## 4. Команды управления модулями

Все команды отправляются в топик `topic_modules` в формате JSON.

### Базовая структура

```json
{
  "device_id":  "A0001",
  "message_id": "01JKY5E122HBQSZKXMF0F7HR44",
  "type":       "<тип модуля>",
  "mode":       "<режим>",
  "action":     "<действие>",
  "schedule_unit": { ... }
}
```

### Поля

| Поле            | Тип    | Обязательно | Описание                                                         |
|-----------------|--------|-------------|------------------------------------------------------------------|
| `device_id`     | string | да          | Идентификатор устройства (должен совпадать с прошивкой)         |
| `message_id`    | string | да          | Уникальный ID сообщения; рекомендуется формат [ULID]            |
| `type`          | string | да          | Тип модуля (см. [раздел 6](#6-типы-модулей-type))               |
| `mode`          | string | да          | Режим работы (см. [раздел 5](#5-режимы-работы-mode))            |
| `action`        | string | да          | Операция над расписанием: `"add"`, `"delete"` или `"none"`      |
| `schedule_unit` | object | да          | Единица расписания; пустой объект `{}` при `"action": "none"`   |

[ULID]: https://github.com/ulid/spec

---

## 5. Режимы работы (`mode`)

| Значение   | Описание                                                                       |
|------------|--------------------------------------------------------------------------------|
| `"off"`    | Модуль выключен                                                                |
| `"on"`     | Модуль включён постоянно (мощность определяется функцией модуля)              |
| `"weekly"` | Управление по расписанию с учётом дня недели (`DD` в интервале = `01`–`07`)   |
| `"daily"`  | Управление по расписанию каждый день (поле `DD` в интервале игнорируется)     |
| `"none"`   | Режим **не изменять** — используется при операциях только с расписанием       |

### Правило: одно сообщение — одна задача

| Цель                      | `mode`                            | `action`               |
|---------------------------|-----------------------------------|------------------------|
| Сменить режим             | `"off"` / `"on"` / `"weekly"` / `"daily"` | `"none"`      |
| Добавить единицу расписания | `"none"`                        | `"add"`                |
| Удалить единицу расписания  | `"none"`                        | `"delete"`             |

> Смешивать изменение режима и операции с расписанием в одном сообщении **нельзя**.

---

## 6. Типы модулей (`type`)

| Значение `type` | Описание                        | Макс. ScheduleUnit | Статус      |
|-----------------|---------------------------------|--------------------|-------------|
| `"led"`         | Светодиод / индикатор           | 4                  | ✅ активен  |
| `"dayLight"`    | Лампы дневного освещения        | 12                 | ⏸ отключён |
| `"uvLight"`     | УФ-лампы                        | 12                 | ⏸ отключён |
| `"heater"`      | Нагреватель                     | 10                 | ⏸ отключён |
| `"humidifier"`  | Увлажнитель воздуха             | 10                 | ⏸ отключён |
| `"fan"`         | Вентилятор                      | 4                  | ⏸ отключён |
| `"waterPump"`   | Насос полива                    | 4                  | ⏸ отключён |
| `"airFlap"`     | Вентиляционная заслонка (серво) | 10                 | ⏸ отключён |

> Активные модули определяются вызовами `modules.AddSetting(...)` в `setup()`.  
> Команды для отключённых модулей вернут код `-3`.

## 7. Управление расписанием

### Добавить единицу расписания

```json
{
  "device_id":  "A0001",
  "message_id": "01JKY5E122HBQSZKXMF0F7HR44",
  "type":       "led",
  "mode":       "none",
  "action":     "add",
  "schedule_unit": {
    "schedule_unit_id": "01JKY5E122ASDF098080ASD8",
    "kind":     "power",
    "interval": {
      "start": "01T06:00",
      "end":   "01T22:00"
    },
    "quantity": {
      "magnitude": 80,
      "unit": "%"
    }
  }
}
```

### Удалить единицу расписания

При удалении нужно передавать **все поля** `schedule_unit` (не только `schedule_unit_id`):

```json
{
  "device_id":  "A0001",
  "message_id": "01JKY5E122HBQSZKXMF0F7HR55",
  "type":       "led",
  "mode":       "none",
  "action":     "delete",
  "schedule_unit": {
    "schedule_unit_id": "01JKY5E122ASDF098080ASD8",
    "kind":     "power",
    "interval": {
      "start": "01T06:00",
      "end":   "01T22:00"
    },
    "quantity": {
      "magnitude": 80,
      "unit": "%"
    }
  }
}
```

## 8. Формат `schedule_unit`

```json
{
  "schedule_unit_id": "01JKY5E122ASDF098080ASD8",
  "kind":     "power",
  "interval": {
    "start": "01T06:00",
    "end":   "07T22:00"
  },
  "quantity": {
    "magnitude": 75,
    "unit": "%"
  }
}
```

### Поле `kind`

| Значение   | Описание                                                                     |
|------------|------------------------------------------------------------------------------|
| `"power"`  | Задать мощность напрямую (`magnitude` = 0–100%)                             |
| `"prefer"` | Поддерживать значение среды (`magnitude` = целевое, напр. `22` при `"C"`)   |

> `"prefer"` недоступен для `led`, `fan`, `airFlap`.

### Поле `interval` — формат `"DDThh:mm"`

```
"DDThh:mm"
  ││  └── минуты (00–59)
  │└───── часы   (00–23)
  └────── день   (01–07)
```

| Режим      | Роль поля `DD`                                            |
|------------|-----------------------------------------------------------|
| `"weekly"` | День недели: `01`=пн, `02`=вт, … `07`=вс. **Обязателен**|
| `"daily"`  | Игнорируется — интервал повторяется каждый день           |

### Поле `quantity`

| Поле        | Тип    | Описание                                               |
|-------------|--------|--------------------------------------------------------|
| `magnitude` | int    | Числовое значение (0–100 для `%`, градусы для `"C"`)  |
| `unit`      | string | `"%"` — проценты, `"C"` — градусы Цельсия             |

## 9. Ответ устройства

На каждую принятую команду ESP32 публикует ответ в топик `topic_response`:

```json
{
  "device_id":  "A0001",
  "message_id": "01JKY5E122HBQSZKXMF0F7HR44",
  "code":       1
}
```

### Коды ответа

| Код  | Описание                                                                          |
|------|-----------------------------------------------------------------------------------|
| `2`  | Успешно: операция с `schedule_unit` выполнена (`add` / `delete`)                 |
| `1`  | Успешно: режим (`mode`) изменён                                                  |
| `-1` | Ошибка: не удалось изменить режим                                                |
| `-2` | Ошибка: операция с `schedule_unit` не выполнена (не найден, лимит, неизвестный `action`) |
| `-3` | Ошибка: неверный `device_id` или неизвестный / неактивный тип модуля            |
| `-4` | Ошибка: JSON не разобран                                                         |

---

## 10. Лимиты расписания

| Модули                              | Макс. `schedule_unit` |
|-------------------------------------|-----------------------|
| `led`, `fan`, `waterPump`           | 4                     |
| `heater`, `humidifier`, `airFlap`   | 10                    |
| `dayLight`, `uvLight`               | 12                    |

При попытке добавить сверх лимита устройство вернёт код `-2`.

## 11. Примеры

### Включить LED

```json
{
  "device_id": "A0001", "message_id": "01JKY5E100000000000000001",
  "type": "led", "mode": "on", "action": "none", "schedule_unit": {}
}
```

### Выключить LED

```json
{
  "device_id": "A0001", "message_id": "01JKY5E100000000000000002",
  "type": "led", "mode": "off", "action": "none", "schedule_unit": {}
}
```

### Перевести LED в режим Daily (ежедневное расписание)

```json
{
  "device_id": "A0001", "message_id": "01JKY5E100000000000000003",
  "type": "led", "mode": "daily", "action": "none", "schedule_unit": {}
}
```

### Добавить расписание LED: 80% с 06:00 до 22:00 каждый день

```json
{
  "device_id":  "A0001",
  "message_id": "01JKY5E100000000000000004",
  "type":       "led",
  "mode":       "none",
  "action":     "add",
  "schedule_unit": {
    "schedule_unit_id": "01JKY5E133HBQS0000000001",
    "kind":     "power",
    "interval": { "start": "01T06:00", "end": "01T22:00" },
    "quantity": { "magnitude": 80, "unit": "%" }
  }
}
```

### Нагреватель: поддерживать 22°C пн–пт с 06:00 до 22:00 (Weekly)

> ⏸ Нагреватель отключён. Раскомментируйте `modules.AddSetting(heater)` в `setup()` перед использованием.

```json
{
  "device_id":  "A0001",
  "message_id": "01JKY5E100000000000000005",
  "type":       "heater",
  "mode":       "none",
  "action":     "add",
  "schedule_unit": {
    "schedule_unit_id": "01JKY5E133HBQS0000000002",
    "kind":     "prefer",
    "interval": { "start": "01T06:00", "end": "05T22:00" },
    "quantity": { "magnitude": 22, "unit": "C" }
  }
}
```
